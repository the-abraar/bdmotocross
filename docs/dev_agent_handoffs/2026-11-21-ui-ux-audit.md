# UI/UX Audit: bdmotocross.com + Paddock (2026-11-21)

Five reviews in one pass: SEO, accessibility (WCAG 2.1 AA), modern web platform guidance, design system, and a design + copy critique of Paddock. Report only: nothing in the code was changed.

> **Status (2026-11-21).** None of the findings below is fixed yet. Already live before this report: the 2026-11-20 modern-web-guidance fixes (`d391bec`..`a3ca539`: dark `color-scheme`, dossier `closedby`, Paddock login/password autofill).
>
> **Pricing rule (owner, 2026-11-21).** The site shows no prices except one line, "Starts from 1,000 BDT", in the enrollment intro (`e1d8d9b`). Don't add prices back anywhere: tiers, JSON-LD `offers`, copy or new pages. Race prize money in rider results is not a price and stays. `js/main.js` still holds the old prices in its dead cost-estimator code; delete them along with `main.js` (§4).

**Method.** Lighthouse 12 (mobile emulation) on 6 live pages, a script that extracts on-page SEO data from every `website/` page, contrast ratios computed from the CSS tokens, a code review of every Paddock page, headless screenshots, 4 web searches for the keyword landscape, and targeted `modern-web-guidance` searches covering the ~80% of the catalogue that `legacy-scan` doesn't check.

## 1. SEO audit (bdmotocross.com)

**Summary.** The pages themselves are solid: every page has exactly one H1, all images have alt text, and titles and descriptions are mostly within length. The problem is discoverability. Only the homepage can be found. Its sharing metadata is broken, there's no sitemap, and four rider pages that could rank for racer names are linked from nowhere. Competition for the core terms is weak: no dedicated motocross club or academy site ranks in Bangladesh. **Verdict: good foundation, critical discoverability gaps.**

## 4. Design system audit (website)

**Summary.** There are two independent systems, and the one the brand docs call the "single source of truth" is no longer what visitors see first. **Score: 48/100.**

| | `site.css` (landing, new) | `styles.css` (subpages, old) |
|---|---|---|
| Size | 631 lines / 44 KB | 4,503 lines / 92 KB |
| Palette | Crest: ink `#0b0b0a`, red `#e3262e`, bone, paper | "Pitch 02": slate `#101216`, red `#dc2626`, silver |
| Type | Anton / Manrope / JetBrains Mono | Unbounded / Space Grotesk / Plus Jakarta Sans |
| Tokens defined / `var()` uses | 23 / 320 | 33 / 525 |
| Hardcoded hex outside tokens | 32 | 72 |
| Hardcoded `rgba()` | 35 | 209 |
| Radius | No radius tokens (50%, 99px, 6px, 40px, 32px, 2px) | `--radius-sm/md/lg` + strays (999px, 4px) |
| Breakpoints | 560 / 820 / 1100 | 580 / 860 / 1024 / 1140 |
| Light theme | No (dark only) | Yes (toggle) |
| Inline `style=""` in pages | 0 | 40–92 per page |
| Documented in | Nothing | `brand.html`, `docs/BRAND_IDENTITY.md` (Unbounded, `#dc2626`) |

16 class names exist in both files with different definitions (`.btn`, `.hero`, `.eyebrow`, `.lightbox`, `.form-status` …), so the same component looks different on the two kinds of page.

**Dead code:** `main.js` (loaded only by the subpages) initialises the cost estimator, lead vault, Feni modal, racer modal and academy form. None of their markup exists on any page; the subpages only need the theme toggle and the gallery filter.

### Recommended consolidation path

1. **Pick `site.css` as the system.** It's the live front door, smaller, and passed the 2026-11-04 UI finish gate.
2. **Rebuild the 4 rider pages + gallery as `site.css` pages** (they become the "Full profile →" targets that SEO item #2 needs). Move inline styles into classes.
3. **Retire `styles.css` and `main.js`**; keep only the gallery filter (~30 lines) in `site.js`.
4. **Drop the light theme toggle** (the landing page has none), or add it to `site.css` deliberately. Not both.
5. **Rewrite `brand.html` / `docs/BRAND_IDENTITY.md` §visual** to the crest system, then `noindex` `brand.html`.
6. Add the missing tokens: radius, spacing scale, and a semantic layer (`--text`, `--text-muted`, `--surface`, `--accent`) over the raw palette.

## 5. Paddock design critique

**Overall.** Strong, consistent dark visual identity (black, rose-600, italic display caps) and excellent speed (Lighthouse 92–100). The biggest problem is product, not visuals: it's a community feed that nobody can post to, with no navigation between its own pages.

### Usability

| Finding | Severity | Recommendation |
|---|---|---|
| No post composer anywhere; feed and race logs permanently empty | 🔴 Critical | Composer at the top of `/feed` for signed-in members (text + image via existing `compressRiderImage` + YouTube link via existing `extractYouTubeId`); `@mentions` util already exists |
| Home CTA "Explore Paddock Feed" leads to an empty feed | 🔴 Critical | Until posts exist, lead with member profiles ("Meet the roster") |
| "Roster Admin" (primary red button) shown to the public and all members | 🟡 Moderate | Render only for `exec` role; redirect non-execs away from `/admin/roster` server-side |
| No app navigation (profile pages have no header; no sign-out; no "My profile") | 🟡 Moderate | One shared header in `layout.tsx` |
| Login has no "how do I get an account?" or "forgot password" path | 🟡 Moderate | "Not a member yet? Join the academy →" (bdmotocross.com/#join) + "Forgot your password? Ask a club executive." |
| Profile: empty grey banner block when no banner | 🟢 Minor | Brand texture/crest fallback, or collapse the banner |
| Dates via `toLocaleDateString()`: profile dates render on the server (UTC, server locale) | 🟢 Minor | Fixed format + `Asia/Dhaka` time zone |
| WhatsApp field placeholder (`settings/page.tsx`) is a real-looking phone number | 🟢 Minor | Use an obviously fake one: `+8801XXXXXXXXX` |

### Visual hierarchy
- **First thing you see:** home: the giant italic club name ✅. Feed: the red "Roster Admin" button outshines the page title ❌ (the admin action is styled as the primary action).
- **Reading flow:** profile card → bio → machine → race log is logical ✅.
- **Emphasis:** "Track Machine" model in rose-500 is a nice racing-programme touch ✅.

### Consistency
| Element | Issue | Recommendation |
|---|---|---|
| Brand | Paddock (rose-600, system font stack: `globals.css` overrides Geist with Arial) vs main site (crest red, Anton/Manrope) | Use the crest red + Anton/Manrope via `next/font` so Paddock feels like the same club |
| Font | `layout.tsx` loads Geist but `body` uses `Arial, Helvetica` | Remove one |
| Buttons | `rounded-lg` vs `rounded-xl` vs `rounded-full` pills used for similar actions | One radius per control type |

### What works
- Fast, simple and clean; ISR profile pages with an edge cache are the right architecture.
- Role badges are clear and colour-coded.
- WhatsApp privacy toggle is a thoughtful default-off.
